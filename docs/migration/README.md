## 1. Qué es el sistema
Refleja (`refleja.org`): sitio estático (Cloudflare Workers, `front/`) con cuestionario de orientación sobre violencia hacia mujeres en Nuevo León. Backend (`api.refleja.org`) solo hace 3 cosas: (1) estadística **anónima** de uso (embudo, municipios, clics de ayuda urgente; sin IP ni PII); (2) login de administradores (Argon2id + Turnstile + JWT con refresh rotatorio); (3) panel `/plataforma` con agregados.
- Consumidor conocido: solo el front propio (`analytics.js`, `auth-common.js`, `acceso.js`, `platform.js`); otros [D] (Q-04).
- Superficie: 15 rutas, 8 tablas, ~1 300 líneas Python, 1 integración externa (Turnstile). Sin Redis/R2/colas/webhooks/WebSockets/jobs/correo. Sin pruebas automáticas en Python.
- Motivo de la migración: RAM (≈130 MB reportados, no medidos; Python `--workers 2`).
- Python: 3.10, FastAPI 0.115.6, Uvicorn 0.32.1, Pydantic 2.10.4, SQLAlchemy 2.0.36 (síncrono), PyMySQL 1.1.1, argon2-cffi 23.1.0, PyJWT 2.10.1, httpx 0.28.1.
- Rust: Axum 0.8 + Tokio + Tower/tower-http, SQLx (solo MariaDB/MySQL, sin SQLite), jsonwebtoken, argon2, hmac/sha2, reqwest (rustls), tracing, thiserror, uuid, rand, lru, dotenvy.

### Arquitectura
```

admin /acceso /plataforma ─login|refresh|platform/*─┤→ Cloudflare (proxy naranja; CF-IPCountry, CF-Connecting-IP)
```

Capas Rust reales (`back-rs/src`): `{app,client,config,db,error,form_meta,municipios,rate_limit,security,timefmt,turnstile,validate}.rs`, `http/{cors,origin_guard,extract}.rs`, `repo/{visitor,counters,form_run,admin}.rs`, `routes/{mod,auth,public,collect,platform,docs}.rs`, `bin/refleja-admin.rs`; `assets/` (Swagger/openapi capturados), `migrations/{0001_baseline.sql,expected_schema.txt}`, `tests/{contract/diff.py,vectors.rs}`, `bench/bench.py`, `scripts/`, `despliegue/`.

### Glosario
`vid` id aleatorio 128 bit del visitante (solo en el JWT del cliente) · `vid_h` = HMAC-SHA256(VID_HMAC_KEY, vid) (lo único en BD) · *run* = un intento del cuestionario (`run_uid`) · `qid` id de pregunta (`pareja_1`, `fam_3`, `trab_x`, `age`, `start`; estados `MINOR/LOCATION/RESULT`) · *reached/answered* = contadores del embudo.

## 2. Contratos que NO deben romperse (spec = comportamiento observable del Python, ADR-009; si doc≠código, gana el código)
1. Paths/métodos EP-001…015 bajo `/api`. Barra final ⇒ 307 a la ruta sin barra. 404/405 `{"detail":"Not Found"|"Method Not Allowed"}` (+`allow`).
2. JSON compacto UTF-8 sin escapar; `detail` string literal en español (listas abajo). 422 = `{"detail":[{type,loc,msg,input,ctx}]}` (Pydantic v2): **status/type/loc contrato; `msg`/`ctx` débil** (ADR-008). JSON malformado ⇒ 422 `json_invalid` (no 400).
3. Códigos: 200, 307, 400 (preflight), 401, 403, 404, 405, 422, 429, (+413 nuevo en Rust). En `/public/collect`, `/public/ping` y `/platform/*` **el 401 precede al 422**.
4. Tokens HS256 con `typ` obligatorio y secretos separados: público `typ=public,vid` (30 d, `X-Refleja-Token`, `PUBLIC_TOKEN_SECRET`); access `typ=access,sub(string),username` (15 min, Bearer, `JWT_SECRET`); refresh `typ=refresh,sub,jti` (7 d, cookie, `JWT_SECRET`). **Intercambiables Python↔Rust** (cutover sin cerrar sesiones); rechazar `alg`≠HS256; un token de otro `typ` no valida.
5. Cookie refresh `refleja_rt`: `HttpOnly; Path=/api/auth; Max-Age=604800; SameSite=lax(config); Secure` si `COOKIE_SECURE` o prod; `Domain` solo si `COOKIE_DOMAIN`. Logout la borra (`Max-Age=0`). **Los 401 de `/auth/refresh` NO llevan Set-Cookie** (quirk, ADR-010).
6. CORS: `CORS_ORIGINS`, credenciales, métodos `GET,POST,OPTIONS`, cabeceras `Authorization,Content-Type,X-Refleja-Token` (+safelisted `Accept,Accept-Language,Content-Language`), `max-age 600`. Preflight válido 200 `text/plain` "OK"; origen no permitido 400 `text/plain` "Disallowed CORS origin".
7. Guard de origen opcional (`ORIGIN_SECRET`/`ORIGIN_SECRET_HEADER=X-Origin-Secret`): solo rutas `/api*`, no `OPTIONS`; falla ⇒ 403 `{"detail":"Origen no autorizado."}` con CORS aplicado; comparación en tiempo constante (Rust).
8. Efectos en BD idénticos: contadores, cuotas por token (2000 eventos/20 runs/300 acciones de por vida; exceso se descarta SIN error), rate limits (120 collect, 30 session, 30 ping por minuto), idempotencia por qid (`form_run.counted`), `form_run.updated_at` actualizado en TODA modificación (realtime ordena por él; `ON UPDATE` de BD no se asume).
9. Fechas UTC naive (`DATETIME`, `SET time_zone='+00:00'`), `metric_date` UTC, ISO sin zona (`isoformat`, sin microsegundos si MariaDB no los da). Rates = `round(x,4)` de Python (`py_round4`, half-even sobre el double exacto, ADR-012). Enteros como enteros. `by_country`/`by_device` con clave **`"None"`** para nulos (FastAPI `jsonable_encoder`; ADR-022).
10. Privacidad: nunca persistir ni loggear IP; solo país (`CF-IPCountry`, `XX`/`T1`/len≠2 ⇒ NULL); `vid` solo como HMAC.
11. Arranque fail-closed en prod (`ENV` que empiece por `prod`, case-insens.): `JWT_SECRET`/`PUBLIC_TOKEN_SECRET`/`VID_HMAC_KEY` por defecto o <32 chars ⇒ no arranca.
12. Escucha `APP_HOST:APP_PORT` (def. `127.0.0.1:20832`; prod Rust 20834 por la unidad). Mismas variables de entorno (§7).
13. Front: reintenta indefinidamente lotes sin `ok` (422/429/5xx tienen efecto operativo); renueva token ante 401; un solo refresh en vuelo.

## 4. `collect` (flujo crítico) y flujos de login
**Body:** `{"events":[≤50]}` o evento suelto (se envuelve); lista vacía ⇒ `accepted:0`. Evento: `type`∈{page_view,run_start,answer,minor,municipio,result,urgent_click,hide_click,restart,directory_municipio}; opcionales `run_uid`(≤36, no UUID), `question_id`(≤32), `next_id`(≤32), `step`0..20, `flow_type`∈{pareja,fam,trab}, `age_bucket`∈{minor,18-25,26-40,41+}, `municipio`(≤48), `risk_level`∈{low,medium,high}, `scores`{psicologica,fisica,economica,patrimonial,sexual,intimidacion: 0..60, def 0}, `device`∈{mobile,desktop,tablet}. Extras ignorados. 422: tipo desconocido, >50, JSON malformado, body ausente, fuera de rango, `run_uid` 37 chars.
**Algoritmo (orden):** 401 → 422 → rate limit → `device` UA (el primer evento con `device` lo sobrescribe, solo al crear visitante) → get_or_create visitor → `Quota` con contadores del visitante → por evento mientras `events_count+d_events < 2000`: procesar; `accepted+=1` **aunque se descarte** → `UPDATE visitor` incrementos atómicos (events/run/completed/action_count, page_views, last_seen_at) → commit (una transacción por petición).
**Por tipo:** `page_view` (acción; si action_count<300: page_views visitor + `daily_metric.page_views`) · `urgent_click|hide_click|restart` (acción; `event_counter[name]+1`) · `directory_municipio` (acción; si slug válido `event_counter["dir_muni:"+slug]+1`, la acción cuenta igual) · `run_start` (started=1, max_step≥1, last_question_id="age", cuenta `age` reached) · `answer` (cuenta question_id answered y next_id reached solo si `qid_ok_for_flow`; started; si trae flow_type: `form_starts+1` la 1ª vez que el run fija flujo y no completado, sobrescribe `flow_type`; age_bucket; max_step; last_question_id = next_id or question_id) · `minor` (started, age_bucket="minor", last="MINOR"; si no completado: completed=1, `minors+1`, `form_completes+1`) · `municipio` (slug válido ⇒ run.municipio, last="LOCATION", no marca started) · `result` (started, last="RESULT", risk_level, municipio válido, **reemplaza los 6 scores** si vienen (ausentes=0); si no completado: completed=1, `form_completes+1`; 2º result solo reescribe risk_level).
**Runs:** evento de run sin `run_uid`, o run inexistente con `run_count+d_runs>=20` ⇒ ignorado. Run identificado solo por `run_uid` global (run ajeno mutable, S-05, preservado). **Idempotencia:** `form_run.counted={"r":[qid],"a":[qid]}`, cada qid una vez por run y tipo (lectura-modificación-escritura sin bloqueo ⇒ posible doble conteo concurrente, S-06). `VALID_QIDS = qids(formulario.json) ∪ {age,start} ∪ {MINOR,LOCATION,RESULT}`; `qid_ok_for_flow(qid,flow)`: intro/terminales siempre; si no, qid del flujo o `flow is None`. Ej.: `answer(pareja_1,next_id=fam_1)` no cuenta fam_1. Municipios: lista cerrada de 52 slugs (51 + `otro`), normalización `"Monterrey"→monterrey`, espacios→guion.
**Login (FL-04):** hash Argon2id PHC `m=65536(64 MiB),t=3,p=4`, salt 16 B, hash 32 B, compatible con argon2-cffi en ambos sentidos; señuelo precalculado (en Rust ya no se calcula al arrancar); re-hash transparente. Cada intento ≈64 MiB transitorios. **Refresh:** estado en `admin_session` (1 fila por refresh; `revoked_at` marca rotación/logout; no se purgan expiradas); token = JWT firmado + `sha256` comparado con `token_hash`. Secuencia real: refresh#1 200 → reuso de la cookie anterior 401 "revocada por seguridad" → la cookie nueva también queda revocada.
**Panel (FL-07):** front hace en paralelo overview,funnel,violence,municipios,timeseries,realtime (+logins?limit=200); `authFetch` renueva access con refresh y reintenta 1 vez.
**Alta de admin (FL-08):** no hay endpoint. Dev Python `python -m app.seed` (admin/admin). Rust: `refleja-admin create-admin --username X` (contraseña por env `REFLEJA_ADMIN_PASSWORD` o stdin, nunca argumento) y `hash-password`. S-15: exigir contraseña explícita.
**Arranque (FL-09):** Python `init_db`: `create_all` (crea `event_counter`) + 5 `ALTER … ADD COLUMN IF NOT EXISTS` (events_count, run_count, completed_count, action_count en `visitor`; `counted JSON` en `form_run`) ignorando errores; `form_meta` lee `formulario.json` al importar (fallback 12/12/12 si falla, ≠ real 13/12/12 [X C-06]; cambiar formulario exige reinicio). **Rust no ejecuta DDL**: `--check`/arranque solo verifican esquema vs `migrations/expected_schema.txt`; `0001_baseline.sql` (idempotente) se aplica a mano si falta algo.

Contadores: `urgent_click`, `hide_click`, `restart`, `dir_muni:<slug>`. Discrepancias históricas: `seed.example.sql` sin `event_counter` (la creaba `create_all`); `create_all` define `updated_at` sin `ON UPDATE` (el `onupdate` era de SQLAlchemy); README Python decía «6 tablas» (son 8); `migration.sql` local vacío; `JSON` en MariaDB = LONGTEXT. Verificación de producción: `refleja-api --check` en el servidor confirmó que el esquema real contiene todo lo que la API usa (resuelve TASK-0002 en lo esencial); versión/sql_mode/GRANTS reales no documentados.
**Escrituras:** incrementos `x=x+n`; Rust usa `INSERT … ON DUPLICATE KEY UPDATE x=x+VALUES(x)` para `question_stat/event_counter/daily_metric` (ADR-007), get-or-create para `visitor`/`form_run`; `updated_at` explícito. **Lecturas:** COUNT, COUNT DISTINCT, `GROUP BY visitor_id HAVING COUNT>1`, SUM de 6 columnas, etc.; `/violence` carga todas las filas completadas (O(n), candidato a agregar en SQL).
**Conexión:** MySQL con `charset utf8mb4`, `SET time_zone='+00:00'`, `READ COMMITTED` por conexión, reintento ≤5× de transacciones de session/collect ante 1213/1205/1020 (ADR-020), `max_lifetime` 1800 s, `DB_MAX_CONNECTIONS`. Sin retención/purga de `visitor/form_run/admin_session/admin_login` (crecen; política [D], Q-09). Backups de MariaDB: gestionados por el dueño (Q-10).
**`formulario.json`:** 39 claves (`age,start,pareja_1..13,fam_1..12,trab_1..12`); el backend lo lee del disco (`front/src/formulario.json` o `FORMULARIO_PATH`) → debe existir junto al binario en el servidor (`/home/refleja-api/htdocs/api.refleja.org/front/src/formulario.json`).
**Integraciones:** Turnstile `POST https://challenges.cloudflare.com/turnstile/v0/siteverify` (form `secret,response,remoteip?`, usa solo `success`, timeout 8 s, sin reintentos, error/timeout/HTTP≠2xx/sin secreto ⇒ rechazar; `TURNSTILE_VERIFY_URL` override para mocks). Cloudflare proxy (cabeceras). CloudPanel/Nginx proxy. Geolocalización `freeipapi.com`/`ipapi.co` es solo del front.
